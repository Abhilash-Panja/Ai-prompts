# Your Task

For the topic I provide, create a **realistic interview question bank containing the questions that are frequently asked in fresher Java interviews**.

Think like an actual interviewer and prioritize questions based on:

# Question Categories

Organize the questions into the following levels.

## 🟢 Level 1 — Fundamental Questions

Questions every fresher should be able to answer.

These should test:

* Definitions
* Basic concepts
* Purpose of the feature
* Basic syntax
* Simple examples

---

## 🟡 Level 2 — Conceptual Understanding

Questions that test whether I actually understand the concept instead of memorizing definitions.

Prefer questions such as:

* Why was this feature introduced?
* What problem does it solve?
* What happens internally?
* Why would we use this instead of another approach?
* What are the limitations?

---

## 🟠 Level 3 — Comparison Questions

Include commonly asked comparisons such as:

> X vs Y

For every important comparison related to the topic.

Examples:

* `ArrayList vs LinkedList`
* `HashMap vs Hashtable`
* `Comparable vs Comparator`
* `String vs StringBuilder vs StringBuffer`

Only include comparisons genuinely relevant to the supplied topic.

---

## 🔴 Level 4 — Tricky / Counter Questions

Include questions interviewers ask to check whether the candidate truly understands the topic.

Examples of the style:

* What happens if...?
* Can we...?
* Why can't we...?
* Is it possible to...?
* What happens internally when...?
* What would happen if we remove/change this?

These should be appropriate for a **0–2 year candidate**, not senior-level trivia.

---

## 🔵 Level 5 — Code-Based Questions

Include short code snippets where the interviewer may ask:

* What is the output?
* Will this compile?
* Will this throw an exception?
* What happens internally?
* Find the mistake.
* How would you improve this code?

Keep the programs small enough to realistically appear in a fresher interview.

---

## 🟣 Level 6 — Scenario-Based Questions

Include practical questions such as:

> Suppose you are building a booking application and multiple users are accessing the same data. How would this concept help?

Where possible, use examples from systems such as:

* Booking applications
* E-commerce
* Banking
* User management
* Backend APIs

Avoid artificial examples unless necessary.

---

# Follow-Up Interview Questions

For important questions, include likely interviewer follow-ups.

Use this structure:

### Q: Why is String immutable in Java?

**Possible Follow-ups:**

* How does immutability help with the String Pool?
* How does it improve thread safety?
* Can you create your own immutable class?
* Is String completely immutable internally?
* What happens when we concatenate Strings?

The goal is to show how an interviewer can start with a simple question and gradually go deeper.

# Important Rules

* Keep the difficulty appropriate for **freshers and 0–2 year Java developers**.
* Prioritize **frequently asked interview questions** over obscure trivia.
* Do not generate hundreds of repetitive questions.
* Merge questions that test exactly the same concept.
* Include both **direct questions and follow-up questions**.
* Include conceptual, coding, scenario, comparison, and tricky questions.
* Focus on understanding rather than memorization.
* Use proper Java terminology.
* Use Markdown formatting.
* Use tables only when they genuinely improve readability.
* Do **not provide detailed answers unless I specifically ask for them**.
* If a question is rarely asked or more suitable for experienced developers, do not prioritize it.
